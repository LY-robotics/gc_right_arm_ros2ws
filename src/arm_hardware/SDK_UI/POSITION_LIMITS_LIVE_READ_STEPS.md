# SDK_UI 六关节位置限位与持续读取：修改步骤

## 1. 确定限位配置

在 `sdk_ui/default_hardware.json` 增加 `joint_position_limits_deg`，按 J1～J6 排列，每个元素是关节角度 `[最小值, 最大值]`，单位为度：

```json
"joint_position_limits_deg": [
  [-148.08, 145.66],
  [-132.36, 6.04],
  [-96.2099, 72.03],
  [-49.9899, 133.73],
  [-166.42, 152.2799],
  [-93.6799, 97.74]
]
```

初始数值从 `src/arm_moveit_config/config/joint_limits.yaml` 的关节弧度范围换算为度，并向内取整。它们是已有规划配置的参考值，**不是实测机械限位**；必须按照实际机械、编码器零位和传动关系确认，必要时留出制动和跟踪误差的安全余量。

界面读取的活动配置是 `~/.config/muweidu_arm_sdk_ui/hardware.json`。首次启动会复制源码默认配置；旧的活动配置没有 `joint_position_limits_deg` 时，SDK 校验阶段从源码默认文件补入，点击“连接 / 应用”后保存。已有该字段的用户值保持不变，不会被默认模板覆盖。修改活动 JSON 后应重启 SDK_UI 并重新连接；只修改源码默认模板不会覆盖已经存在的活动限位。

## 2. 验证限位配置

修改 `sdk_ui/arm_sdk.py` 的 `ArmSdk._validate_config()`：

1. 无限位字段的旧配置，从随 SDK 安装的 `default_hardware.json` 读取默认限位；默认文件也不可用时拒绝连接，不能绕过限位。
2. 必须恰有六组各两个数字；最小值和最大值均为有限数，且最小值严格小于最大值。错误配置产生明确异常。
3. 解析后的数值存入 SDK 配置，提供后续所有目标检查。

## 3. 统一检查全部位置入口

新增 `_check_joint_position_limits()`，在 `_move_from_snapshot()` 中统一调用。UI 的手动绝对位置、增量、Demo0～Demo5 和逻辑回零都会经过此路径。

绝对位置采用输入的六关节目标。增量位置先读取六电机 `0x92` 多圈位置，反算当前关节角，再计算每个关节 `目标 = 当前位置 + 增量`。只要任意目标超出该关节范围，提示关节编号、目标和范围，整个动作在发送任何位置命令前被拒绝；不单独截断关节目标，以免改变运动意图。

## 4. 检查电机协议量化后的目标

六关节目标先通过耦合矩阵换算成六电机目标，应用电机方向和零偏；按电机 `0xA4` 的 0.01° 分辨率进行与发送代码一致的编码。将编码后的六电机绝对目标再反算为逻辑关节目标，重新检查六轴限位。任何名义目标、量化目标或电机协议整数范围不合法，均在发出第一条电机位置命令前拒绝。比较仅允许 1e-9° 的浮点计算容差，并非放宽电机量化级别。

## 5. 增量发送改为绝对目标

此前 `move_increment()` 读取位置并计算后向电机发送 `0xA8` 相对增量。若电机在读取后、实际接收命令之前继续运动，0xA8 使用接收时的位置作为起点，最终位置可能超出依据旧读数计算的目标。

现在仍以一次刚读取的当前位置作为增量计算基准，但将计算出的目标转换为电机**绝对目标**，通过 `0xA4` 发送；目标检查与普通绝对位置一致。六台电机仍逐台读、逐台发送，因此反馈快照不是同时采样，实际运动中仍需验证。

## 6. 增加持续读取按钮

修改 `sdk_ui/app.py`，在当前绝对位置区域增加“开始持续读取 / 停止持续读取”：

1. 按下开始后，后台线程依次读取六台电机的 0x92 位置，在 Tk 主线程刷新关节和电机角度。
2. 每次完整读取结束后等待 250 ms，再发起下一次；串行 CAN 耗时叠加到间隔，因此这是周期性显示，不是固定频率的硬实时采样。最多只允许一个读取任务在途。
3. 周期读取只刷新界面，不覆盖或保存 Demo0；原来的“读取绝对位置并保存 Demo0”仍由用户主动触发。
4. 点击停止、关闭窗口、重连、启用 CAN 或执行编码器设零时停止轮询。用代次排除停止前旧请求的迟到结果；读取失败时停止轮询，清除旧显示并提示错误。
5. 持续读取正在进行时，用户操作可等待当前读取完成后执行；急停优先于尚未执行的普通操作。已经开始的 CAN 事务不能被界面中断，急停可能需要等待读取/超时，不能替代独立硬件急停。

## 7. 使用限制

软件检查的是**目标位置**，不是机械式限位开关，也不是对实际全路径的连续保护：六个电机顺序发送、耦合、电机超调、已在执行的旧命令、编码误差和通信失效都可能使实际轨迹偏离。越界被拒绝后不会自动更改原先已经运行的电机命令；真实机械仍需要经过验证的限位开关、独立急停和足够安全余量。

编码器硬件设零、方向、零偏或传动矩阵变化会改变逻辑关节坐标与限位的关系；修改后应重新校准。避免 SDK_UI 和 ROS 等多个程序同时控制同一 CAN 总线。

## 8. 验证

在 SDK_UI 目录执行：

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q sdk_ui
```

无硬件测试覆盖六轴绝对/增量越界、协议量化和耦合反算、旧配置迁移、Demo/回零共用校验、持续读取开始/停止、异常和旧回调，以及用户操作与急停优先级。实际 CAN 时序、机械限位和 GUI 仍需现场验证。

本次运行结果：SDK_UI 全部 56 项无硬件测试通过，`compileall` 通过。测试使用模拟电机与界面事件，未向 CAN 总线发送命令。当前环境无可用图形显示和实体电机，不能确认实际界面布局、机械行程或电机通信表现。源码启动可直接使用新代码；若使用 colcon 安装或非 editable Python 安装副本，需要先重新构建或重新安装。
