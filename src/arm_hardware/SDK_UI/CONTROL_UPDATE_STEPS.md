# SDK_UI 设零、Demo 采集与逐关节启停：修改步骤

## 1. 修改目的

在已有的六电机一键运行、关断、急停和 Demo 功能上，新增电机当前位置设零、Demo1～Demo5 实时采集当前位置，以及每个逻辑关节关联电机的运行和关断。保持现有一键控制以及 Demo0 的专用读取流程。

## 2. 添加底层设零协议

文件：`sdk_ui/protocol.py`。

在 `CanMotor` 中添加 `set_current_position_as_zero()`：发送八字节 `19 00 00 00 00 00 00 00`，使用已有 SocketCAN 事务机制校验电机 ID、命令码及帧长度；从回复的 DATA6～7 按小端序读取编码器零偏并返回。此命令写入电机 ROM；超时只表示没有收到确认，不能断定电机没有执行，代码不自动重试。

## 3. 添加六台电机设零操作

文件：`sdk_ui/arm_sdk.py`。

1. 新增 `MotorZeroResult`，逐台记录 `motor_id`、回复的 `encoder_zero_offset` 或未确认时的 `error`。
2. 新增 `set_current_positions_as_zero()`；在操作锁保护下，按配置顺序对每台电机各执行一次设零。
3. 一台失败时继续尝试其余电机，返回六台各自的结果，方便界面显示确认和未确认状态。
4. 不自动改写 SDK 的 `motor_zero_offset_deg`、ROS 的零偏或 Demo 配置。协议资料不能保证设零后 0x92 多圈角立刻为零，必须重新读取并核验实际标定。

## 4. 添加设零按钮

文件：`sdk_ui/app.py`。

1. 新增“电机编码器设零 (0x19)”按钮，与原有“移动到逻辑零位”分开：前者修改电机编码器零点，后者发送运动目标。
2. 点击设零先检查连接，并弹窗说明 ROM 持久写入、标定和已保存 Demo 可能受影响，要求操作者确认。
3. 确认后清除原有位置显示，在后台执行设零；界面逐台显示已确认的编码器零偏或未确认的错误。
4. 操作后提示重新读取位置和核验软件零偏、ROS 坐标及 Demo；未确认时特别提示不要仅凭超时判断写入失败。

## 5. 添加逐关节关联电机控制

文件：`sdk_ui/arm_sdk.py`。

1. 新增 `joint_motor_ids(joint_index)`，按照当前 `joint_to_motor` 矩阵对应列的非零项找到关联电机。SDK 接口的关节索引为 0～5。
2. 新增 `joint_motor_on()` 和 `joint_motor_off()`，分别对这些电机发送现有的 0x88 和 0x80 命令。
3. 在操作锁保护下逐台尝试；发生错误后继续尝试其余关联电机，并汇总已确认和未确认的电机 ID。
4. 一键运行、关断和急停仍控制所有电机，并保留逐台尝试与错误汇总。

默认矩阵下：J1 → M1；J2 → M2、M3；J3 → M2、M3；J4 → M4、M5；J5 → M5；J6 → M6。M1～M6 指配置列表中的电机顺序，并不一定等于 CAN ID。J2/J3 及 J4/J5 存在共享电机，单关节按钮实际会影响其他关联关节。

## 6. 添加逐关节界面按钮

文件：`sdk_ui/app.py`。

新增 J1～J6 各自的“运行”和“关断”按钮；使用后台线程调用 SDK，成功后在反馈区显示涉及的实际电机 ID。界面提示共享电机的影响，原有六电机一键按钮保持可用。

## 7. 添加 Demo 当前位置采集

文件：`sdk_ui/app.py`。

1. Demo1～Demo5 每一行增加“读取并写入当前位置”按钮；Demo0 保持原有专用读取按钮。
2. 按钮先通过 `read_positions()` 读取六台电机的 0x92 多圈位置，并通过映射矩阵反算六个逻辑关节角。
3. 读取成功后，在新副本中替换所选 Demo，并通过临时文件写入 `~/.config/muweidu_arm_sdk_ui/demo_positions.json`，写入成功后再更新内存和界面。
4. 读取或写入失败时不替换原有 Demo；读取成功还会更新当前关节及原始电机位置显示。
5. 文件保存读取的浮点精度；输入框显示四位小数，移动时按输入框的值发送。

## 8. 文档及验证

`README.md` 已更新按钮、耦合影响、设零语义和启动路径，并以 `sdk_ui/default_hardware.json` 为准修正源码默认 ID 和速度上限的说明。已有用户的 `hardware.json` 不会被更新自动覆盖。

使用 Python 标准库模拟 CAN 和 UI 状态验证协议、设零结果、关节关联、部分失败处理和 Demo 保存；测试不需要真实电机。建议在 SDK_UI 目录执行：

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q sdk_ui
```

实机时应先核对 CAN ID、映射、零偏、速度上限及电机状态。编码器设零是持久标定操作；部分确认或超时后应先检查硬件状态。实际 CAN/电机和图形界面显示仍需在目标设备上验证。
