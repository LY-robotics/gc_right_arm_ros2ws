# SDK_UI：CAN 启用和六电机三环 PI 修改步骤

## 1. 目标与适用范围

在独立 SDK_UI 中新增 CAN 接口配置按钮，以及六台电机三环 PI 参数读取、逐台永久写入和本地历史记录。位置/速度/转矩三环 PI 是电机驱动内部参数，与 ROS 轨迹控制器的 PID 参数是两套不同参数。

## 2. 新增 CAN 接口启用

新增 `sdk_ui/can_setup.py`，主界面 `sdk_ui/app.py` 的 CAN 区域增加“启用 CAN（1 Mbps）”。

1. 从界面 CAN 输入框读取接口名，验证名称为合法的 1～15 字符；读取 `/sys/class/net/<接口>/type`，必须为 Linux CAN 类型 `280`，避免对非 CAN 网络接口执行 down。
2. 用户确认通信将中断后，关闭 SDK 当前连接并在后台线程依次执行下列步骤（以下以 can2 为例）：

   ```bash
   ip link set dev can2 down
   ip link set dev can2 type can bitrate 1000000
   ip link set dev can2 up
   ```

3. 使用系统绝对路径的 `ip` 命令、参数数组及 `shell=False` 默认行为，不拼接 shell 命令；非 root 时优先 `pkexec`，如无 pkexec 则尝试 `sudo -n`。使用 pkexec 时三步可能分别请求授权；程序不获取或保存密码。
4. 任何步骤失败立即停止后续步骤，报告已完成的步骤和接口可能仍处于关闭状态；完成后用户需重新点击“连接 / 应用”。按钮设置的是 CAN 网络接口，不是给电机上电。

使用前请确认目标接口、波特率和机械臂已停止并安全支撑；切断 CAN 可能中断其他进程与电机的通信。

## 3. 新增电机三环 PI 协议

修改 `sdk_ui/protocol.py`：

- 新增 `PidGains`，六个字段按 CAN 协议字节顺序排列：位置 Kp、位置 Ki、速度 Kp、速度 Ki、转矩 Kp、转矩 Ki。每个字段是 0～255 的原始整数；这个范围来自字段宽度，不代表稳定或安全的调参范围。
- `CanMotor.read_pid()` 发送 `0x30`，从回复 DATA2～DATA7 解出六个值。
- `CanMotor.write_pid_rom()` 发送 `0x32`，DATA2～DATA7 为新值；响应数据与请求不一致视为未确认。
- 电机文档说明 `0x32` 写 ROM、断电不丢失；实际 ROM 应答格式和掉电保持需要在对应设备上验证。当前回读只能验证读到的当前参数，不能替代断电后复查。

## 4. 新增单电机 SDK 读写及历史

修改 `sdk_ui/arm_sdk.py`：

1. `read_pid(index)` 读取一台电机，索引从 0 开始。
2. `write_pid_persistent(index, gains, expected_old)` 接收新参数和此前读取的原值；持操作锁时先重新读取，若当前值与此前显示的基准不一致，则拒绝写入；若新旧值相同则不执行 ROM 写入。
3. 开始写入前向 `~/.config/muweidu_arm_sdk_ui/pi_history.jsonl` 追加 `intent` 记录并执行持久化同步；记录包含唯一操作 ID、UTC 时间、接口、M 序号、CAN ID、原始值和目标值。如果意图无法记录则不发 `0x32`。
4. 只发送一次 `0x32`，不自动重试。无论应答是否确认，尝试再次读取 `0x30`；追加同操作 ID 的 `result`，包括状态、回读值和错误。
5. 丢失应答、回读失败或回读不一致分别标记未确认/不一致；即使读取到了目标值，丢失写入应答也不当作已确认。结果记录写入失败时会明确提示“电机可能已经改变”，不得盲目重试。
6. JSONL 是本地顺序记录，意图和结果为独立行；意图存在但结果缺失可能意味着程序在写入期间中断，不能推断设备状态。它不是防篡改日志。

## 5. 新增六电机 PI 界面

新增 `sdk_ui/pi_panel.py`，主界面通过“六电机三环 PI 参数”按钮打开独立窗口：

- 每台电机分别显示灰色只读的“读取值”和可编辑的“待写入”区域，并显示 M1～M6、实际 CAN ID 与读取/永久写入按钮；支持读取全部六台。
- 必须先成功读取当前连接的对应电机，才能写入；读取失败或连接身份改变时清除写入基准。
- 写入前逐项展示原值与新值并要求确认。写入开始后使旧基准失效；写入未确认时需重新读取和核验，不能直接盲目重试。
- 成功表示写入应答已确认且当前参数回读一致，并明确告知断电后的持久性仍需在安全条件下重启电机并读取验证。
- CAN 操作在后台线程执行；GUI 更新回到 Tk 主线程。

## 6. 使用和安全说明

1. 确认设备型号、CAN ID、接口和波特率；先确保电机已停并安全支撑机械臂，避免 ROS 或其他工具同时使用总线。
2. 点击“启用 CAN（1 Mbps）”，按系统提示完成授权；成功后连接 SDK。
3. 打开 PI 窗口并读取对应电机；记录和核实初始值后再调整和写入。
4. 检查应答、当前值和历史文件；若未确认，先核验设备，勿自动或盲目重复写 ROM。按设备操作规范验证重启持久性。

修改 PI 会影响驱动稳定性，程序不替用户推断参数安全值；所有回路的值必须按电机资料及实机条件确认。

## 8. 读取和写入区域分离

PI 面板对每台电机提供灰色只读的当前读取值，以及独立的待写入编辑框。读取成功后将设备值填入两个区域；随后编辑只影响待写入值。读取失效或写入结果未确认时，清除只读区和写入基准，保留待写入草稿并要求重新读取；写入成功并回读一致后同步显示最新值。已有 ROM 二次确认及本地历史记录流程保持不变。
