# 六轴机械臂硬件 SDK 调试界面

`SDK_UI` 是独立的 Python 调试工具，通过 Linux SocketCAN 直接与六个实际电机通信。关节模式使用逻辑关节角（°），SDK 按耦合和减速比矩阵换算到电机侧。笛卡尔直线模式使用 `base_link` 下的末端坐标（m）。

本工具直接操作实体硬件。可在连接区启用静态绳驱补偿，使用 `arm_hardware` 的共享库、参数与机械臂 URDF 几何计算电机位置和静态反馈。补偿默认关闭，启用后点击「连接 / 应用」加载配置。离线调试使用工作区的 `arm_tendon_test` 包。

发送运动命令前先核对电机映射并确认机械臂周边防护。SDK_UI 的位置指令直接发送给电机，碰撞检测由外部系统负责。

## 安装条件

- Linux 系统，且电机 CAN 总线已配置为 SocketCAN 网络接口。
- Python 3.10 或更新版本。
- Tkinter。若系统未安装，可按发行版安装 `python3-tk`（例如 Debian/Ubuntu：`sudo apt install python3-tk`）。
- 笛卡尔 FK、IK 和直线规划使用 NumPy，安装本包时随依赖安装。SDK 无需 ROS 或 `python-can`。

## 安装与启动

在工作区根目录执行：

```bash
cd /home/xlh/桌面/ros2_ws_2/ros2_ws/src/arm_hardware/SDK_UI
python3 -m pip install -e .
muweidu-arm-sdk-ui
```

也可以不安装命令行入口，直接启动：

```bash
cd /home/xlh/桌面/ros2_ws_2/ros2_ws/src/arm_hardware/SDK_UI
python3 -m sdk_ui.app
```

如果已经通过 colcon 安装了 `arm_hardware`，SDK_UI 文件也会安装在 ROS 包的 `share/arm_hardware/SDK_UI` 目录下；Python 独立运行时仍需能找到 `sdk_ui` 包。日常开发推荐从源码目录使用上面的 editable 安装方式。

## 配置 CAN

可在界面输入实际 CAN 接口名，点击“启用 CAN（1 Mbps）”；程序检查接口类型、请求管理员授权，并依次执行关闭、设置 1000000 bit/s、启用。认证可能弹出多次；若没有 pkexec，程序尝试 `sudo -n`，需要事先配置无交互授权。中途失败时界面会提示接口可能仍处于关闭状态。操作完成后点击“连接 / 应用”。

也可在终端手动配置。下面以 `can2` 和 1 Mbit/s 为例；接口名和波特率必须与实际设备一致：

```bash
sudo ip link set can2 down
sudo ip link set can2 type can bitrate 1000000
sudo ip link set can2 up
```

也可以用 `ip link show` 查看当前接口状态。界面默认 CAN 口为 `can2`，六个示例 Motor ID 为 `1, 2, 3, 4, 5, 6`；这些 ID 是默认值，请按电机实际配置修改并确保每个 ID 唯一。

## 界面操作

| 控件 | 功能 |
| --- | --- |
| CAN 接口、Motor IDs | 配置总线接口和 M1～M6 的电机 ID。修改后点击“连接 / 应用”。 |
| 启用 CAN（1 Mbps） | 对选中的 CAN 接口执行 down、设置 1000000 bit/s 和 up，需管理员授权；操作后重新连接 SDK。 |
| 六电机三环 PI 参数 | 在独立窗口读取和逐台写入位置、速度、转矩环 Kp/Ki（0x30/0x32）。写入 ROM 前确认并记录历史。 |
| 统一关节速度上限 | 设置一次动作的公共关节速度上限，单位为度/秒（°/s）。 |
| 运行 | 对六个电机发送运行命令（一键运行）。 |
| 关断 | 对六个电机发送关断命令（一键关断）。 |
| J1～J6 的运行 / 关断 | 对映射矩阵中该关节关联的所有电机运行或关断，关联电机可能与其他关节共享。 |
| 急停 | 对六个电机发送急停命令。 |
| 读取状态 | 读取六个电机的状态信息，包括温度、电压、电流、状态/故障位、原始 Iq、速度和编码器字段。 |
| 读取绝对位置并保存 Demo0 | 使用 0x92 读取六个电机的多圈绝对角度，换算并显示当前逻辑关节位置，同时把当前位置保存为 Demo0。 |
| 开始 / 停止持续读取 | 周期性读取和显示六关节位置，完成一次读取后等待 250 ms 再请求；不会自动覆盖 Demo0。 |
| 发送绝对位置 | 将手动输入的六个关节目标位置（度）换算为电机目标位置并发送。 |
| 发送增量位置 | 读取当前位置，加上六个关节增量后校验限位，并作为电机绝对位置目标发送。 |
| 移动到逻辑零位 | 以当前统一速度上限，将六个逻辑关节的绝对目标设为 0 度；这是运动命令。 |
| 读取 FK 并填入 XYZ | 读取当前六轴反馈，显示末端位姿，并把当前 XYZ 填进目标框。 |
| 执行直线 / 停止直线 | 按输入的 XYZ 规划直线路点，逐段跟踪并自动保存末端反馈 CSV。停止时保留已采集记录。 |
| 电机编码器设零 (0x19) | 经确认后，依次对六台电机发送当前编码器位置设零命令，写入电机 ROM。详见下方说明。 |
| Demo0～Demo5 | 每行可将对应的六轴关节位置作为绝对目标移动。Demo0 由读取绝对位置自动更新；Demo1～Demo5 可编辑、保存和调用，也可以分别点击“读取并写入当前位置”。 |
| 每行的“零点往返循环” / “停止循环” | 启动后使能六电机，先到逻辑零位，再在零位和该 Demo 之间往返；持续读取位置，六轴连续两次进入到位误差后换向。再次点击停止并发送急停。 |
| 循环到位误差 | 默认 0.1°，按六轴最大位置误差判断；开始循环时固定本次目标、速度和误差参数。 |

成功读取位置后，界面会显示反算出的六个关节角以及 0x92 返回的电机多圈角度。执行位置命令时，反馈区域会显示预估公共运动时长、未限幅的电机速度需求和应用电机速度上限后的发送值。

## 笛卡尔直线运动

面板里的 `base_link` 对应当前 URDF 中名为 `base` 的基座坐标系。末端取 `Arm6` 坐标系原点及朝向，使用描述包的六轴原点、轴向和限位。如果独立安装的 SDK 找不到描述包，可以设置 `ARM_TENDON_URDF` 指向对应的 URDF。 [机械臂几何](../../arm_description/urdf/Arm_R.urdf.xacro)

1. 连接 SDK，点击「运行」使能电机，并等待机械臂停稳。
2. 可点击「读取 FK 并填入 XYZ」查看起点。在 XYZ 框填入目标坐标（m），设置直线规划速度（mm/s）、关节速度上限和 CSV 保存目录。
3. 点击「执行直线」。IK 沿直线求连续关节解，保持起始末端朝向。程序先检查整条路径的关节、补偿与电机目标，再逐段发送位置指令，并按末端反馈推进。目标超出固定朝向下的可达范围时会在预检阶段报错。
4. 执行时面板显示反馈推算的 XYZ、RPY、线速度和直线偏差。每次运行单独保存 CSV，默认目录为 `~/.config/muweidu_arm_sdk_ui/cartesian_traces/`。位置和朝向来自六轴实际 `0x92` 读数的 FK，速度用相邻采样差和实测时间间隔估算。启用绳驱补偿时沿用 SDK 的补偿指令和静态反解反馈。

规划路点间距最多 5 mm。每段连续两次满足位置误差 ≤1 mm、朝向误差 ≤1° 且最大关节误差 ≤0.12° 后才推进。反馈超出线段 3 mm、偏离起始朝向 3°、超时或通信失败时停止后续指令并尝试急停。电机通过顺序发送的 A4 指令运动，直线速度输入用于规划，实际轨迹和速度由采样反馈估计。

CSV 记录 UTC 时间、相对时间、目标和反馈 XYZ（m）、反馈四元数和 RPY（°）、线速度向量及大小（m/s）、角速度向量及大小（rad/s）、直线偏差（m）和六轴反馈（°）。采样间隔目标为 50 ms，实际周期包含 CAN 事务耗时，首条采样的速度字段留空。最后一行标记完成、取消或失败。运动中点击「停止直线」、急停或关闭窗口时，程序会先停止后续运动并保存已采集的轨迹。

## Demo 往返循环

Demo0～Demo5 各有“零点往返循环”按钮，零点表示六个逻辑关节角均为 0；启动前同时校验零位和 Demo 限位。Demo 与零点的距离小于等于到位误差时拒绝无意义循环。循环先到零位，再按 `零位 → Demo → 零位` 重复；连续两次全轴到位才发送下一段，不能只靠预计时长换向。

主窗口增加纵向滚动条；内容超过窗口高度时可滚动到全部 Demo 操作和反馈区域。

循环自动启用持续位置读取，完成一次读取后间隔 250 ms，实际刷新还包括通信时间；不自动覆盖 Demo0。界面显示本段目标、最大位置误差和往返次数。原先已开启的持续读取在停止循环后保留；由循环开启的读取随循环停止。

再次点击同一行“停止循环”、点击急停/关断或关闭窗口会取消后续目标。停止循环发 0x81；关断发相应 0x80。位置读取、目标发送失败，或单段超过 `max(10秒, 3×预计时长+5秒)`，也会停止循环并尝试全轴急停。停止不能中断已经进入电机的指令或阻塞的 CAN 事务，需等待当前事务序列结束。循环中阻止其他位置命令、连接变更和编码器设零；修改 Demo 输入不会改变已经启动的循环目标。

本 SDK 独立于 MoveIt，循环速度沿用 UI 的统一关节速度输入。ROS 的自适应系数 k 不应用到独立 SDK。完整修改与测试见 [修改记录](../ADAPTIVE_SPEED_AND_DEMO_CYCLE_CHANGE_STEPS.md)。

## 设零和逐关节控制

“电机编码器设零 (0x19)”将六台电机当前位置依次写入各自的编码器零位 ROM，会弹出确认框并逐台报告确认结果。通信超时只能说明结果未确认，电机可能已经写入，请先检查，不要直接重复写入。软件配置中的 `motor_zero_offset_deg`、ROS 配置及已保存的 Demo 不会自动修改；0x92 多圈读数是否变为零取决于电机行为，因此设零后请重新读取并核验标定。该按钮与“移动到逻辑零位”是不同操作。

每个关节的运行 / 关断根据当前 `hardware.json` 的 `joint_to_motor` 矩阵选取电机。以源码默认矩阵为例，J1 → M1，J2 → M2/M3，J3 → M2/M3，J4 → M4/M5，J5 → M5，J6 → M6；这里的 M1～M6 是配置中电机的顺序，实际 CAN ID 由 `motor_ids` 决定。J2、J3 共享电机，J4、J5 也共享 M5，所以不能对这些关节实现完全独立的电机使能。

Demo1～Demo5 的“读取并写入当前位置”会重新读取六台电机并保存该行；读取或保存失败时不替换原来的 Demo。Demo0 仍通过专用读取按钮保存。界面显示和移动使用四位小数，配置文件保存读取值的原始精度。

## 电机三环 PI 参数

点击“六电机三环 PI 参数”，每台电机分别显示灰色只读的“读取值”和可编辑的“待写入”区域，包含位置、速度和转矩环的 Kp/Ki 及实际 CAN ID。读取成功后两区初始值相同，编辑待写入值不会改变读取值。可逐台读取或点击“读取全部六台”；只有读取成功的电机才能永久写入。数值为协议原始字节 `0～255`，不是已知的安全调参范围。

永久写入前显示原值和新值并要求确认；SDK 再读取并检查原值是否变化，把修改意图记录到本机文件，再发送 `0x32`。随后用 `0x30` 回读并记录结果。回读一致只能确认当前读取值，不能证明掉电后 ROM 一定保存成功；持久性应按设备要求在安全条件下重启后重新读取验证。通信超时或应答不一致可能已经写入，不会自动重试。

历史文件为 `~/.config/muweidu_arm_sdk_ui/pi_history.jsonl`，每次写入尝试包含操作 ID、时间、电机 ID、接口、原值、目标值及结果；意图和结果是独立记录。若意图不能写入，程序不向电机发送写入命令；若结果记录失败，设备可能已改变，需检查电机并勿盲目重试。文件是本机记录，并非防篡改审计。

调整 PI 前应停止并安全支撑机械臂，避免 ROS 控制器或其他 CAN 程序同时操作同一电机；参数改变可能影响稳定性。

## 关节位置限位

SDK 的 `hardware.json` 中 `joint_position_limits_deg` 依次为 J1～J6 的 `[最小角度, 最大角度]`，单位为关节度。首次启动从源码 `sdk_ui/default_hardware.json` 复制到 `~/.config/muweidu_arm_sdk_ui/hardware.json`；旧配置缺少这一项时，连接时自动补入源码默认值并保存。**已有该项的用户配置不会被源码默认值覆盖**。修改本机配置后需重启 SDK_UI 再连接。

直线规划在 SDK_UI 角度约定下取 SDK 限位与换算后 URDF 限位的交集。如果 J2 零位一致、正方向相反，先把本机 `joint_position_limits_deg` 的第二项设为 `[-6.04, 132.36]` 并重启 SDK_UI，再在连接区勾选「J2 方向与 URDF 相反」并点击「连接 / 应用」。也可以在本机 JSON 顶层填写 `"j2_urdf_direction": -1` 后重启并连接。这个选项使 UI 的 J2 +30° 对应 URDF 的 −30°，FK、IK 和静态绳驱补偿均使用这个换算。反馈角、命令角和 CSV 中的 J2 仍使用 SDK_UI 角度约定。配置缺省时采用同向的 `1`。

默认值从本工作区 MoveIt 关节限制向内取整，并非对实体机械限位的测量；使用前必须按实机的方向、零位和装配进行标定。绝对目标、增量目标、Demo 和回零均在发送前检查六轴逻辑关节目标以及电机 0.01° 编码后反算的目标，任何一轴越界则不发位置命令。增量功能读取一组当前位置，计算 `当前位置 + 增量`，再以 `0xA4` 绝对目标下发；这避免 `0xA8` 在电机接收时以已变化的位置作为增量起点。

这是**软件目标限位**，不保证实际运动过程中不超调、不碰撞或不越过物理限位；CAN 逐台读取/发送、机械耦合、位置误差及断线都会影响实际轨迹。编码器设零或更改方向/零偏/映射后须重新标定。持续读取为串行请求，实际刷新间隔还包括六台电机通信时间；急停可优先等待当前请求完成后执行，不能中断已经阻塞的 CAN 事务，不能替代独立急停。

## 速度上限与换算

统一速度输入 `V` 是关节空间的速度上限。SDK 根据刚读取的位置 `q0` 和目标位置 `q1` 计算关节位移 `Δq = q1 - q0`，再使用硬件映射矩阵计算电机位移 `Δm`。六台电机按相同的运动时间规划，因此各电机速度随本次映射位移成比例。

公共运动时间至少满足关节速度限制；如果任何一台电机将超过自身安全速度上限，SDK 会拉长公共运动时间，再按相同比例计算六台电机的速度。这样可避免耦合动作中只对某个电机单独降速而改变运动路径。

例如只移动关节 1，若关节速度上限输入为 `100°/s`，按当前映射 `m1 = -36 × 2.8 × q1`，电机 1 的理想未限幅速度需求为 `100 × 36 × 2.8 = 10080°/s`。实际发送值会受到配置中的电机速度上限约束，公共运动时间也会相应延长。**不要把示例速度理解为实际电机一定能达到的速度。**

## 配置文件

首次启动时，默认硬件映射会复制到：

```text
~/.config/muweidu_arm_sdk_ui/hardware.json
```

这里可配置 CAN 口、电机 ID、电机方向、零偏、电机速度上限和 `joint_to_motor` 映射矩阵。位置单位为度；方向值应为 `+1` 或 `-1`。如果修改耦合矩阵，必须确认与 hardware 包中供 ros2_control 使用的矩阵一致，否则 SDK 调试和 ROS 控制会采用不同的坐标映射。

源码默认配置中的电机速度上限为 `[1230, 1390, 1390, 1480, 5030, 4300]°/s`。已存在的用户配置不会因源码更新而自动覆盖，应检查实际 `hardware.json`。请先核对实际电机协议对速度字段的单位、减速器位置和安全速度，再调整这些值。电机 ID、方向和零偏也必须依据实机标定，默认值仅供配置起点使用。

Demo 位置保存于：

```text
~/.config/muweidu_arm_sdk_ui/demo_positions.json
```

## 实机操作注意事项

1. 首次操作前确认 CAN 接口、六个电机 ID、转向、零偏、映射矩阵和速度上限。
2. 确保机械臂周围没有人员或障碍物，并能随时使用电机急停或断电。
3. 先用较低的关节速度和很小的位置增量检查每个轴的方向和实际响应，再进行较大幅度动作。
4. 本界面绕过 MoveIt 和 ROS 轨迹执行，不提供规划场景碰撞检查；运动目标需要由操作者确认安全。
5. CAN 命令按电机逐个发送，六个电机的命令并非硬件同步下发。发生部分通信失败时，SDK 会尝试对所有电机发送急停。
6. 状态中的 Iq 是协议原始反馈值，未经标定，不能直接当作 N·m 扭矩读数。
